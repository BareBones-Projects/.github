## Priority gates

**P0 Security:** TruthMeta tracked SQLite runtime WAL/SHM artifacts; confirm removal from release tree, inspect historical access, harden default credential and wildcard CORS. BareMark payment/identity/inventory authority must remain private until auth, replay/concurrency and ledger tests pass. Any secrets or actual user data found in history require dedicated incident review.

**P0 Engine:** GATE's actual default branch is `alpha`, not `main`. Require Linux Unreal 5.8.4 compile, PIE/standalone/cook and plugin dependency tests before a release-candidate PR. Keep design/asset validation distinct from gameplay/runtime acceptance.

**P1 Frontend and launcher:** Tuna-Browser and Remedy-Launcher require clean OS packaging, signed artifact verification, navigation/URL handling tests and security boundary review. BareTextures requires an environment template, stable tests, API usage limits and secure deployment architecture.

**P1 Map systems:** ALT-celestial-map-web, ALT-celestial-map-unreal-engine, alt-star-map-db, alt-cyclus-map, alt-void-cartography and ALT-hub-ui-master need explicit data-contract version compatibility and reproducible import/snapshot validation. Avoid merging incompatible schemas or moving content to unrelated repos without migration plans.

**P2 Asset and themes:** theme packs, CSS, shaders, 3D assets and web demos need preview-based READMEs, install/uninstall steps, validation scripts and downloadable releases with SHA-256 manifests.

## Review workflow
1. Create isolated changes on a branch from each repo's **observed** default branch; keep PRs as draft until tests verify release gates.
2. Report complete and incomplete tests, exact commands/versions, code review findings, artifact names and SHA-256 hashes.
3. Protect `main`, `master`, and `alpha` as appropriate; never push speculative fixes directly to protected branches.
4. Do not auto-merge repositories into one codebase; central coordination is not source consolidation.
5. Archive release evidence under `docs/release/` and attach preview captures to the README when they represent actual running builds.

## Standard release evidence
- [ ] README with purpose, architecture, installation, usage, limitations and actual screenshots
- [ ] SECURITY.md and reviewed data/secrets handling
- [ ] CI smoke tests, unit tests and negative-path scenarios
- [ ] Verified clean install and uninstall, rollback for updaters
- [ ] License and dependency review
- [ ] Versioned release notes, changelog and reproducible checksummed package
- [ ] Reviewer approval before alpha promotion

**Status:** This inventory and set of gates are planning artifacts. They do not constitute functional or security certification.
